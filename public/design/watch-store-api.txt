WATCH STORE E-COMMERCE — API ROUTES Architecture: NestJS Modular
Monolith | MongoDB + Mongoose | REST + Socket.IO Base URL: /api/v1

AUTHENTICATION & CONVENTIONS

Auth header: Authorization: Bearer Roles: GUEST, CUSTOMER, ADMIN,

SUPER_ADMIN Pagination: ?page=1&limit=20&sortBy=createdAt&sortOrder=desc
Use DTO validation, ownership checks, role guards, rate limits, and
consistent error responses. Never trust client-supplied userId, role,
price, discount, stock, or payment status. Use idempotency keys for
checkout and provider callbacks.

Discount types: percentage, fixed_amount. Rules: validate active status,

min(subtotal * rate, maxDiscount) when cap exists. Fixed amount:

checkout when limits require concurrency protection. Confirm usage after
successful payment; release on failed/expired checkout. Store couponCode
and discount snapshot on the Order.

19. SOCKET.IO REAL-TIME API

Namespace: /realtime Authentication: JWT in Socket.IO handshake auth
payload. Example: io(“https://api.example.com/realtime”, { auth: {
token: “” } })

Rooms: user:{userId} Private user room admins Authorized admins
admin:{adminId} Private admin room order:{orderId} Authorized order
subscribers watch:{watchId} Optional watch updates

Client -> Server: order:subscribe order:unsubscribe inventory:subscribe
inventory:unsubscribe watch:subscribe watch:unsubscribe

Server -> Client: realtime:ready realtime:error order:created
order:confirmed order:processing order:shipped order:delivered
order:cancelled order:status-updated payment:pending payment:succeeded
payment:failed payment:refunded shipment:created shipment:status-updated
shipment:delivered inventory:updated inventory:low-stock
inventory:out-of-stock inventory:back-in-stock watch:price-updated
watch:price-dropped notification:new notification:read
notification:count-updated

Admin events: admin:order:new admin:order:updated admin:payment:failed
admin:inventory:low-stock admin:review:new admin:customer:new

Socket security: - Derive userId and role from verified JWT, never
client claims. - Authorize every room join; verify order ownership. -
Restrict admin rooms by role. - Validate payloads and rate-limit client
events. - Clients must not emit trusted events such as payment:succeeded
or order:delivered. - Use Redis Socket.IO adapter for multiple backend
instances. - Consider transactional outbox for reliable event delivery.

20. CHECKOUT BUSINESS FLOW

1.  Authenticate customer and load cart.
2.  Revalidate products, variants, prices, and quantities.
3.  Validate address, shipping method, and coupon on the server.
4.  Start MongoDB transaction.
5.  Atomically reserve stock.
6.  Reserve coupon capacity when applicable.
7.  Create PENDING order with immutable item/address/discount snapshots.
8.  Commit transaction.
9.  Initialize payment with provider.
10. Verify signed provider webhook.
11. On success: mark payment succeeded, confirm order, finalize stock,
    confirm coupon usage, create shipment workflow, persist
    notification, then publish real-time events.
12. On failure/expiry: fail/expire order, release stock and coupon
    reservations, and notify customer.

Inventory quantity model: - availableQuantity = units available for new
purchases. - reservedQuantity = units reserved by pending checkouts. -
Reserve: available -= quantity; reserved += quantity. - Payment success:
reserved -= quantity (units are sold). - Release: reserved -= quantity;
available += quantity. Use atomic updates and an expiry job. MongoDB
multi-document transactions require a replica set.

22. IMPLEMENTATION CHECKLIST

-   Validate every REST and Socket.IO payload with DTOs/schemas.
-   Enforce authentication, roles, and resource ownership.
-   Keep business logic in services, not controllers or gateways.
-   Keep payment/shipping providers behind adapter interfaces.
-   Use MongoDB replica set transactions for checkout operations.
-   Use atomic stock updates to prevent overselling.
-   Use idempotency for checkout and webhook processing.
-   Persist notifications before emitting Socket.IO events.
-   Add indexes for email, slug, SKU, orderNumber, userId + createdAt,
    coupon code, and unread notification queries.
-   Never store plain-text passwords, OTPs, or refresh tokens.
-   Keep payment and webhook secrets in environment variables.
-   Record sensitive admin operations in audit logs.
